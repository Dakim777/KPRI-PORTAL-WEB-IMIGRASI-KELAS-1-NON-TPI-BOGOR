4.5.5. Perancangan Basis Data (Database)

Rancangan tabel-tabel utama yang diterapkan pada basis data MySQL 8.0 Sistem Portal KPRI Kantor Imigrasi Kelas I Non-TPI Bogor adalah sebagai berikut:

Tabel 4.1. Struktur Tabel users
Nama Field Tipe Data Keterangan
idBigInt (PK)Auto increment, identifier utama pengguna
nameVarChar(255)Nama lengkap pengguna / petugas kasir
emailVarChar(255)Email unik pengguna (kredensial login)
passwordVarChar(255)Kata sandi terenkripsi (Bcrypt)
roleEnumHak akses akun (super_admin, kasir_paspor)
remember_tokenVarChar(100)Token penjelajah untuk fitur Remember Me
created_atTimestampWaktu pembuatan akun pengguna
updated_atTimestampWaktu pembaruan data akun
deleted_atTimestampWaktu penghapusan akun (Soft Delete)
Tabel 4.2. Struktur Tabel transaksi_paspors
Nama Field Tipe Data Keterangan
idBigInt (PK)Auto increment, primary key
kasir_idBigInt (FK)Relasi ke tabel users.id (Kasir pemproses)
id_transaksiVarChar(50)ID Unik Transaksi (format KBG-YYMMDD-XXX)
no_strukIntNomor urut kwitansi transaksi
nama_penerimaVarChar(255)Nama pemohon paspor (Terenkripsi AES-256)
jumlah_pasporIntJumlah fisik buku paspor yang dikirim
nama_paspor_listTextRincian nama pemilik paspor (Terenkripsi AES-256)
alamat_tujuan_pengirimanTextAlamat pengiriman paspor (Terenkripsi AES-256)
no_hpTextNomor WhatsApp pemohon (Terenkripsi AES-256)
no_resiVarChar(100)Nomor resi pengiriman dari kurir (Nullable)
jenis_kurirVarChar(50)Ekspedisi kurir (pos, jne, sicepat, tiki, dll)
layanan_kurirVarChar(100)Jenis paket layanan ekspedisi kurir
metode_pembayaranVarChar(50)Metode pembayaran transaksi (Tunai / QRIS)
total_pembayaran_pemohonDecimal(12,2)Total tagihan pembayaran yang dibayar pemohon
biaya_kurirDecimal(12,2)Biaya ongkir asli dari pihak ekspedisi
handling_feeDecimal(12,2)Biaya jasa penanganan Koperasi (Handling Fee)
tanggal_transaksiDateTanggal pencatatan transaksi paspor
status_pengirimanEnumStatus alur (transaksi, diproses, selesai, batal)
created_atTimestampWaktu pembuatan record transaksi
updated_atTimestampWaktu pembaruan record transaksi
deleted_atTimestampWaktu transaksi dihapus (Soft Delete)
Tabel 4.3. Struktur Tabel activity_log
Nama Field Tipe Data Keterangan
idBigInt (PK)Auto increment, primary key
log_nameVarChar(255)Nama kategori log audit (default, paspor)
descriptionTextDeskripsi rincian aktivitas operasional
subject_typeVarChar(255)Nama model target yang diubah
subject_idBigIntID record target yang diubah
causer_typeVarChar(255)Nama model pengguna pelaksana aktivitas
causer_idBigInt (FK)ID user pelaksana (Relasi ke users.id)
propertiesJsonRekam nilai sebelum dan sesudah (Old & New Values)
eventVarChar(255)Jenis kejadian (created, updated, deleted)
created_atTimestampWaktu pencatatan aktivitas operasional
Tabel 4.4. Struktur Tabel notifications
Nama Field Tipe Data Keterangan
idChar(36) (PK)Primary key unik berformat UUID
typeVarChar(255)Nama kelas notifikasi sistem Laravel
notifiable_typeVarChar(255)Kelas model target penerima (App\Models\User)
notifiable_idBigInt (FK)ID user penerima notifikasi (Relasi ke users.id)
dataTextData payload notifikasi JSON (Zero PII Plaintext)
read_atTimestampWaktu notifikasi dibaca pengguna (Nullable)
created_atTimestampWaktu notifikasi dibuat
Tabel 4.5. Struktur Tabel sessions
Nama Field Tipe Data Keterangan
idVarChar(255) (PK)Primary key unik hash sesi browser
user_idBigInt (FK)ID user terautentikasi (Relasi ke users.id, Nullable)
ip_addressVarChar(45)Alamat IP perangkat pengguna
user_agentTextInformasi browser & OS pengguna (User Agent)
payloadLongTextData sesi login terenkripsi Laravel
last_activityIntTimestamp UNIX waktu aktivitas terakhir
